# OneKey QR

[![CI](https://github.com/takyoto/onekey-qr/actions/workflows/test.yml/badge.svg?branch=main)](https://github.com/takyoto/onekey-qr/actions/workflows/test.yml)

[English](README.md) | 日本語

**スマホと同じくらい手軽に、パソコンの画面のQRコードを。キーを1回押すだけで読み取れます。**

スマホならカメラを向けるだけで読めるQRコードも、パソコンではスマホを取り出して画面を撮るなど、手間がかかりがちです。OneKey QR は常駐して動き、`Win+Shift+Q` を押すと画面に表示されているQRコードを読み取って、その内容をクリップボードにコピーします。

- マルチモニター全体からQRコードを探します
- 画面内に複数のQRコードがあれば、すべて読み取ります
- 丸いドットやロゴ入りのデザインQR、白黒反転（ダークモード）のQR、日本語（UTF-8・Shift_JIS／漢字モード）も読み取れます
- コピーが終わると、コピーした内容をトースト通知で表示します

## 動作環境

- Windows 11
- Python 3.10 以上

## インストール

```
pip install -r requirements.txt
```

使用するライブラリは次のとおりです。

| ライブラリ | 用途 |
|---|---|
| mss | 画面（マルチモニター全体）をキャプチャする |
| zxing-cpp | QRコードを検出・デコードする（マイクロQR・rMQR にも対応） |
| numpy | 画面キャプチャを読み取り処理に渡す |
| pyperclip | 読み取った結果をクリップボードへコピーする |
| win11toast | トースト通知を表示する |

## 使い方

1. スクリプトを起動します。

   ```
   python onekey_qr.py
   ```

   起動すると、コンソールに次のように表示されます。

   ```
   OneKey QR is running: press WINDOWS+SHIFT+Q to read QR codes (Ctrl+C to quit)
   ```

2. 読み取りたいQRコードを画面に表示します。
3. `Win+Shift+Q` を押します。
4. トースト通知が出たら、`Ctrl+V` で貼り付けられます。
5. 終了するときは、スクリプトを起動したコンソールで `Ctrl+C` を押します。

### ホットキーの登録について

スクリプトは起動時に、`Win+Shift+Q` をシステム全体のホットキーとして Windows に登録します。`Win+Shift+S`（スクリーンショット）など、Windows 標準のショートカットと同じ仕組みです。

- スクリプトが動いている間は、Windows がこのキー操作をスクリプトに渡し、前面のアプリには渡しません。テキスト入力欄でホットキーを押しても、`Q` は入力されません。
- 登録は、スクリプトが動いている間だけ有効です。スクリプトを終了すると Windows が自動で登録を解除し、キーは元どおりに使えます。レジストリや設定ファイルには何も書き込みません。
- ホットキーの登録に、管理者権限は要りません。
- 同じ組み合わせを Windows や他のアプリがすでに使っている場合は、`Error: WINDOWS+SHIFT+Q is already used by Windows or another app.` と表示して終了します。その場合は、別のホットキーにしてください（[ホットキーの変更](#ホットキーの変更)を参照）。

### 読み取り結果

| 状況 | クリップボードの中身 | 通知 |
|---|---|---|
| QRコードが1つ | その内容 | `Copied: （内容）` |
| QRコードが複数 | 改行区切りですべての内容 | `Copied N items: （内容の一覧）` |
| 見つからない | 変更なし | `No QR code found` |

## ホットキーの変更

`onekey_qr.py` の冒頭にある `HOTKEY` を書き換えます。キーは `+` でつなぎ、修飾キー（`windows` または `win`、`ctrl`、`alt`、`shift`）を0個以上と、最後にキーを1つ書きます。最後のキーには、英字、数字、`f1`〜`f24`、`space`、`pause`、`scroll lock`、`insert`、`home`、`end`、`page up`、`page down` が使えます。

```python
HOTKEY = "windows+shift+q"
```

ホットキーを選ぶときは、**押す順番を間違えたときに、途中で成立する組み合わせが危なくないか**に注意してください。
たとえば `Ctrl+Alt+Q` は、Alt より先に Q を押すと `Ctrl+Q` になり、アプリによっては終了してしまいます。

| 設定例 | 備考 |
|---|---|
| `"windows+shift+q"` | 既定。途中で成立するのは `Win+Q`（検索）か `Shift+Q`（Qの入力）だけ |
| `"scroll lock"` / `"pause"` | 1キーで安全。ただしノートPCには無いことが多い |

## 注意事項

- 画面のキャプチャはメモリ上で処理し、画像ファイルは保存しません。
- QRコードが小さすぎたり、一部が隠れていたりすると読み取れないことがあります。拡大して再度試してください。
- `win11toast` が入っていない場合は `plyer` で通知を試し、どちらも無ければコンソールに結果を表示するだけになります。
- トースト通知が表示されない場合は、Windows の通知設定を確認してください。通知が出なくても、QRコードの読み取りとコピーは行われ、結果はコンソールに表示されます。
  - **設定 → システム → 通知** で、「通知」がオンになっているか
  - 「応答不可」（Windows 11）または「集中モード」（Windows 10）がオフになっているか
  - 同じ画面のアプリ一覧で、送り主のアプリ（Windows PowerShell や Python など）がオフになっていないか

## 開発

開発用の依存ライブラリを入れて、テストを実行します。

```
pip install -r requirements-dev.txt
pytest
```

テストの対象は、QRコードの読み取り（segno で作ったQR画像と、Google Chrome で作った丸いドットのQRコードを使用）と、読み取りからコピー・通知までの流れ（画面キャプチャ・クリップボード・通知は偽物に差し替え）です。ホットキーの解釈、Windows への登録、ホットキーのメッセージの処理もテストしています。実際にホットキーを押したときの動作、本物の画面キャプチャ、トースト通知は Windows のデスクトップ環境に依存するため、手で動かして確認してください。
